Pourquoi la décision « achat dans l'app » est la plus urgente

Aujourd'hui, l'application ouvre la page de paiement SATIM pour acheter un abonnement. Apple et Google demandent en général leur propre système de paiement pour ce type d'abonnement. L'option 1 se met en place en une demi-journée de développement : l'écran « Offres » de l'app affiche les offres et un bouton « S'abonner sur gofix-digital.dz » ; un abonnement payé sur le site est reconnu immédiatement dans l'app (mêmes comptes).

PAIEMENTS DE BOUT EN BOUT

Ce qui existe déjà, et ce qu'il reste à obtenir

Comment fonctionne un paiement

1. CommandeL'utilisateur choisit une offre ; le serveur crée une commande
2. Page SATIMCarte CIB / Edahabia saisie sur la page sécurisée de la SATIM (jamais chez GoFix)
3. RetourLa SATIM renvoie vers l'URL de retour ; l'app est rouverte par le lien gofix://
4. VérificationLe serveur redemande le statut à la SATIM avant toute activation
5. ActivationAbonnement actif, notification, facture PDF
ÉlémentÉtatDétail
✓Paiement SATIM sur le site et dans l'appPrêtPage SATIM hébergée, retour dans l'app, vérification serveur
✓Réglage depuis le back-officePrêtMot de passe chiffré, test de connexion sans débit
✓Factures PDF et historique des commandesPrêtAvec l'identité de la société saisie dans Admin → Société
✓Protection contre le double paiement / double activationPrêtActivation atomique, rappels SATIM limités
☐Contrat commerçant et accès SATIMBanqueTest puis production, après recette
☐Décision « achat dans l'app »DirectionVoir section 1
☐RemboursementsHors appPas de bouton de remboursement dans GoFix : ils se font depuis l'espace commerçant de la banque

À ne jamais faire

  • Activer le paiement « simulé » en production : le serveur le refuse, et il ne faut pas contourner ce blocage.
  • Transmettre les accès SATIM par e-mail ou les écrire dans le code ou le fichier .env d'un poste : ils se saisissent uniquement dans le back-office.

RÉPONSES PRÉPARÉES

Questions probables de l'équipe pendant l'appel

Code et installation

Où est le code de l'application ?

Dans le dépôt GitHub gofix-mvp, dossier mobile/ (l'ancien dépôt gofix-v1 n'est plus utilisé). Écrans : src/app (une route = un fichier) ; appels au serveur : src/api ; composants : src/components ; thème et éléments d'interface : src/theme.js, src/ui.

Quelle technologie ?

React Native avec Expo (SDK 57) et expo-router. Une seule base de code pour Android et iOS. Pas besoin de Mac : les builds iOS se font dans le cloud d'Expo (EAS).

Comment lancer l'app sur mon téléphone ?

cd mobile, npm install, npx expo start, puis scanner le QR code avec Expo Go (même Wi-Fi que le PC). En développement, l'app utilise automatiquement le serveur lancé sur le PC ; pour viser un serveur en ligne : EXPO_PUBLIC_API_URL=https://gofix-digital.dz npx expo start.

À quel serveur se connecte l'app installée ?

À https://gofix-digital.dz, réglé dans eas.json pour les builds preview et production. Le serveur doit donc être en ligne en HTTPS avant de construire l'application.

Comment modifier un texte ou une traduction ?

Les textes sont partagés avec le site : modifier frontend/src/i18n/fr*.js et ar*.js, puis lancer npm run i18n:sync dans mobile/. Ne pas modifier directement mobile/src/i18n/shared.

Pourquoi l'app redémarre quand on passe en arabe ?

L'arabe se lit de droite à gauche : le téléphone doit recharger l'application pour inverser la mise en page. Dans Expo Go, un message demande de recharger manuellement ; dans l'app installée, le rechargement est automatique.

Builds et stores

Quelle différence entre les profils preview et production ?

preview produit un APK Android à installer directement sur les téléphones de test. production produit les fichiers pour les stores (AAB pour Google Play, IPA pour l'App Store) et augmente automatiquement le numéro de build.

Qui garde les clés de signature ?

EAS (Expo), sur le compte de l'organisation gofix-digital. Ne jamais les supprimer : sans la clé Android, plus aucune mise à jour n'est possible sur Google Play.

Comment publier une mise à jour ?

Augmenter version dans app.json (ex. 1.0.0 → 1.0.1), lancer le build production, puis eas submit. Les mises à jour « à distance » sans passer par les stores (EAS Update) ne sont pas configurées pour l'instant : chaque mise à jour passe par une revue des stores.

Les liens réseaux sociaux, bannières et vidéos demandent-ils une nouvelle version ?

Non. Ils se règlent dans le back-office (Communication, Bannières pub) et apparaissent dans l'app en quelques minutes. Seuls les changements de code ou de traductions demandent une nouvelle version.

Que donner aux testeurs d'Apple et de Google ?

Deux comptes créés en production depuis Admin → Utilisateurs (un client, un professionnel), avec leurs identifiants dans les notes de revue. Les comptes de démonstration @gofix.dz n'existent pas en production.

Pourquoi l'app pourrait-elle être refusée ?

Principalement pour l'achat d'abonnement sans le système de paiement du store (voir section 1). Autres causes fréquentes : compte de test qui ne fonctionne pas, politique de confidentialité inaccessible, captures d'écran qui ne correspondent pas à l'app.

Fonctionnalités

Les notifications ne marchent pas dans Expo Go, est-ce un bug ?

Non : Expo Go ne reçoit pas les notifications distantes sur Android. Il faut tester avec le build preview après avoir configuré Firebase (phase 4).

Les notifications sont-elles en temps réel ?

Oui pour les messages, les rendez-vous et les réponses aux demandes : le serveur les envoie immédiatement via le service push d'Expo. Elles peuvent être coupées globalement dans le back-office (flag push_notifications).

Que fait l'app de la position de l'utilisateur ?

Elle n'est demandée que lorsque l'utilisateur touche « Détecter ma wilaya » ou « Près de moi », reste approximative, et n'est jamais enregistrée par GoFix. La localisation précise et en arrière-plan sont bloquées dans la configuration Android.

Où sont stockées les sessions sur le téléphone ?

Dans le stockage sécurisé du système (SecureStore : Keychain sur iOS, Keystore sur Android), jamais en clair.

Comment se passe le paiement dans l'app ?

L'app ouvre la page SATIM dans un navigateur sécurisé ; après paiement, la SATIM renvoie vers le serveur, qui rouvre l'app par le lien gofix://payment/result. L'écran de résultat redemande toujours le statut au serveur : un paiement n'est jamais validé par l'app elle-même.

Et si l'utilisateur ferme l'app pendant le paiement ?

Le serveur reçoit quand même le retour de la SATIM et active l'abonnement. À la réouverture, Abonnement & factures affiche le bon statut. Une commande non payée expire après 30 minutes (réglable).

Sécurité et audit

npm audit signale des vulnérabilités, faut-il corriger ?

Elles concernent les outils de build d'Expo (Metro, CLI, plugins), pas le code livré dans l'app, sauf une (decode-uri-component, risque très faible). Ne pas lancer npm audit fix --force : il rétrograde Expo et casse l'app. Elles disparaîtront avec la mise à jour vers Expo SDK 58.

Comment vérifier que le projet est sain ?

npx expo-doctor doit afficher « 21/21 checks passed ». Après une mise à jour d'Expo : npx expo install --fix.
