3. Règles d'or

  • Jamais de mot de passe dans le code, le dépôt Git, un e-mail ou une messagerie. Le fichier .env du serveur reste sur le serveur.
  • Toujours sauvegarder avant de modifier (le script de déploiement le fait automatiquement pour la base).
  • Ne jamais charger les données de démonstration en production : seule la commande --reference-only est autorisée (le script refuse l'autre).
  • L'ancienne version n'est pas supprimée avant 30 jours : elle est sauvegardée puis simplement plus servie.
  • Aucune mise en ligne si un test automatique échoue.

4. Point bloquant connu : accès SSH

Le port SSH (22) et le port aaPanel (8888) ne répondaient pas en octobre 2026

Test du 13/10/2026 : le serveur répond au ping et sur les ports 80/443, mais pas sur 22 ni 8888 (filtrés côté Algérie Télécom, pas côté client). Avant le jour J, demander au support VPS d'Algérie Télécom : (1) le port SSH réel, (2) l'ouverture de SSH et du port 8888 depuis l'IP publique de l'équipe (ou à tous pour SSH si l'IP change souvent ; on sécurise ensuite par clé), (3) l'existence d'une console web de secours. Vérification depuis un PC Windows (PowerShell) :

Test-NetConnection 197.112.108.20 -Port 22      # TcpTestSucceeded : True attendu
Test-NetConnection 197.112.108.20 -Port 8888

Si un autre port est attribué (ex. 2200) : ssh -p 2200 … et scp -P 2200 … (P majuscule pour scp).

C

MISE EN LIGNE DU SERVEUR

9 étapes, ≈ 1 h 30 — le site gofix-digital.dz passe sur GoFix V1

Principe

Sur le VPS, aaPanel garde les ports 80/443 et le certificat HTTPS ; GoFix tourne dans Docker sur 127.0.0.1:8080 et aaPanel lui transmet le trafic. Deux scripts font le travail : scripts/package_release.ps1 (sur le PC : prépare l'archive) et scripts/deploy.sh (sur le serveur : sauvegarde, installe, démarre, vérifie). Ils ont été répétés à l'identique en conditions de production le 14/10/2026 (installation, mise à jour, sauvegarde, restauration).

1

Se connecter au serveur 5 min

ssh root@<IP>

Répondre yes à la première question, saisir le mot de passe (rien ne s'affiche, c'est normal). Le serveur impose un nouveau mot de passe root à la première connexion : saisir l'ancien puis deux fois le nouveau, le ranger dans le gestionnaire de mots de passe, se reconnecter.

Résultat attendu : une invite du type root@…:~#. Erreur « Connection timed out » : voir A.4.
2

Préparer le serveur (une seule fois) 15 min

apt update && apt -y upgrade
free -h ; df -h /                    # conseillé : 4 Go de RAM, 20 Go libres
grep -c avx /proc/cpuinfo            # doit être > 0 (sinon : Dossier technique, F.3)
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
curl -fsSL https://get.docker.com | sh
docker compose version
Résultat attendu : Docker Compose version v2.x.
3

Sauvegarder l'ancienne version (une seule fois) 10 min

mkdir -p /root/ancienne-version
tar czf /root/ancienne-version/site-$(date +%F).tar.gz /www/wwwroot/gofix-digital.dz
cp -r /www/server/panel/vhost/nginx /root/ancienne-version/vhost-nginx-$(date +%F)
ls -lh /root/ancienne-version

Dans aaPanel → Databases : sauvegarder la ou les bases de l'ancien site. Télécharger ensuite /root/ancienne-version et ces sauvegardes sur un PC.

Résultat attendu : une archive site-AAAA-MM-JJ.tar.gz non vide et une copie sur un autre support.
4

Préparer et envoyer le code (depuis le PC) 5 min

# PowerShell, dans le dossier gofix-mvp
powershell -ExecutionPolicy Bypass -File scripts\package_release.ps1
scp ..\gofix-release.tar.gz root@<IP>:/opt/
Résultat attendu : « Archive ready … (≈ 2 Mo) » puis transfert à 100 %. L'archive ne contient ni .env, ni secrets, ni application mobile.
5

Créer la configuration de production (sur le serveur) 10 min

mkdir -p /opt/gofix && tar xzf /opt/gofix-release.tar.gz -C /opt/gofix
cd /opt/gofix
cp .env.example .env && chmod 600 .env
openssl rand -hex 32        # 3 fois : JWT_SECRET, CONFIG_ENCRYPTION_KEY, mot de passe MongoDB
nano .env                   # Ctrl+O pour enregistrer, Ctrl+X pour quitter

Valeurs à renseigner (les autres lignes peuvent rester telles quelles) :

APP_ENV=production
FRONTEND_URL=https://gofix-digital.dz
CORS_ORIGINS=https://gofix-digital.dz,https://www.gofix-digital.dz
JWT_SECRET=<valeur 1>
CONFIG_ENCRYPTION_KEY=<valeur 2>
ADMIN_EMAIL=<adresse de l'administrateur principal>
ADMIN_PASSWORD=<12 caractères minimum, lettres et chiffres>
MONGO_ROOT_USER=gofix_root
MONGO_ROOT_PASSWORD=<valeur 3>
MONGO_URL=mongodb://gofix_root:<valeur 3>@mongo:27017/?authSource=admin
HTTP_BIND=127.0.0.1:8080
HTTPS_BIND=127.0.0.1:8443

Important

Les lignes MONGO_ROOT_* doivent être renseignées avant le premier démarrage (elles ne s'appliquent qu'à une base neuve). Le paiement et les e-mails peuvent être réglés plus tard (D).

6

Installer et démarrer GoFix 5 à 15 min

bash scripts/deploy.sh
Résultat attendu : le script se termine par « Déploiement terminé », affiche {"status":"ok","db":true,…}, les référentiels ('wilayas': 58 …) et 4 services « Up ». En cas d'« ERREUR », le script affiche la cause (souvent une valeur du .env refusée par les garde-fous de production : corriger puis relancer la même commande).
7

Brancher le domaine et le HTTPS dans aaPanel 10 min

  1. Website → site gofix-digital.dz (ajouter www.gofix-digital.dz dans les domaines s'il manque).
  2. Onglet SSL → Let's Encrypt → cocher les deux domaines → Apply → activer Force HTTPS.
  3. Onglet Reverse proxy → Add : nom gofix, URL cible http://127.0.0.1:8080, domaine envoyé $host.
  4. Onglet Config : vérifier/compléter puis enregistrer :
client_max_body_size 10m;
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 60s;
}
Résultat attendu : https://gofix-digital.dz affiche l'accueil GoFix avec le cadenas ; http:// redirige vers https://.
8

Réglages dans le back-office 10 min

Se connecter sur https://gofix-digital.dz/admin avec ADMIN_EMAIL, puis :

  • Société & mentions légales : renseigner raison sociale, RC, NIF, NIS, article d'imposition, adresse du siège, directeur de la publication, e-mails de contact et de signalement, déclaration ANPDP. Ces informations s'affichent dans les CGU, CGV, mentions légales, politique de confidentialité (site et application) et sur les factures ; un champ vide apparaît « [à compléter] ». Cocher « Textes validés par un juriste » après relecture juridique.
  • Moyen de paiement : choisir SATIM, saisir les accès de test, Enregistrer, Tester la connexion (détail en D.2).
  • Utilisateurs : créer les comptes nominatifs de l'équipe (inscription normale), puis leur attribuer le rôle moderator ou support.
  • Paramètres : vérifier les prix des offres ; plus tard, coller les liens app_store_url et play_store_url (E.6).
  • Feature flags : laisser les valeurs par défaut (modules « à venir » désactivés).
9

Sauvegarde automatique quotidienne 2 min

crontab -e
# ajouter la ligne suivante (base de données chaque nuit à 2 h 30, 14 jours conservés) :
30 2 * * * cd /opt/gofix && bash scripts/backup_mongo.sh >> backups/backup.log 2>&1
Résultat attendu : bash scripts/backup_mongo.sh lancé à la main affiche « Backup OK » et crée un fichier dans /opt/gofix/backups. Copier ce dossier chaque semaine hors du serveur.
D

SERVICES À BRANCHER

E-mails, paiement en ligne, SMS

D.1 E-mails (Admail d'Algérie Télécom)

  1. Admail → Gérer mes comptes → Ajouter un nouveau compte : login no-reply, mot de passe généré, type Basic.
  2. Obtenir du support d'Algérie Télécom le serveur SMTP sortant et son port (465 SSL ou 587 STARTTLS).
  3. Back-office (super-admin) → onglet E-mails → « Serveur SMTP (envoi réel) ». Adresses : expédition no-reply@gofix-digital.dz, nom affiché GoFix, réponse contact@gofix-digital.dz. Serveur : nom SMTP, sécurité/port, identifiant (adresse complète), mot de passe → Enregistrer. Effet immédiat, sans redémarrage ; le mot de passe est chiffré et jamais réaffiché.
  4. Envoyer le test vers votre adresse → « E-mail de test envoyé » attendu. Sinon le message indique la cause (identifiants refusés, serveur injoignable, adresse d'expédition refusée).
  5. Contrôle final : « Mot de passe oublié » sur un compte de test → l'e-mail arrive (vérifier aussi les indésirables).
  6. Secours : les variables EMAIL_PROVIDER/SMTP_* du .env ne servent que tant que rien n'a été enregistré dans le back-office.

D.2 Paiement CIB / Edahabia (SATIM)

  1. Back-office → Moyen de paiement → « SATIM – CIB / Edahabia », environnement test, URL de l'API, identifiant, mot de passe, Terminal ID → Enregistrer → Tester la connexion (« Connexion réussie » attendu).
  2. Communiquer à la SATIM/banque l'URL de retour affichée sur le même écran.
  3. Vérifier que les pages /legal/cgv, /legal/mentions, /legal/privacy n'affichent plus aucun « [à compléter] » (informations saisies dans l'onglet Société & mentions légales).
  4. Espace cibweb.dz → « Certification sites web marchands » : dérouler les scénarios demandés (paiement accepté, refusé, annulé…) depuis https://gofix-digital.dz/pricing ; les numéros de commande sont visibles dans le back-office → Paiements.
  5. Après validation : saisir les accès de production dans le même écran (environnement « Production »), tester, puis faire un premier paiement réel de faible montant.

Tant que SATIM n'est pas réglé

Le site fonctionne normalement ; seul l'achat d'abonnement affiche « paiement momentanément indisponible ». Le paiement simulé est interdit en production.

D.3 SMS (facultatif)

La connexion par code SMS est désactivée par défaut. Pour l'activer : passerelle SMS algérienne avec API HTTP, variables SMS_PROVIDER=http, SMS_HTTP_URL, SMS_HTTP_TOKEN, SMS_SENDER_ID dans le .env, puis flag auth_phone_otp dans le back-office.

E

PUBLICATION DE L'APPLICATION

Google Play et App Store — identifiant d'application dz.gofix.app

Décision à prendre AVANT de soumettre : achat d'abonnement dans l'application

L'application permet aujourd'hui d'acheter les abonnements GoFix par la page SATIM. Or Apple (règle 3.1.1 de l'App Store) et Google (règles de paiement de Google Play) exigent en général leur propre système de paiement intégré pour les abonnements qui débloquent des contenus ou fonctions numériques dans l'application. Risque : refus lors de la revue. Options : (1) dans les applications, masquer l'achat et inviter à s'abonner sur le site (les abonnements achetés sur le site restent reconnus dans l'app, mêmes comptes) ; (2) intégrer les achats intégrés Apple / Google (développement supplémentaire, commission des stores) ; (3) soumettre tel quel en argumentant la mise en relation avec des services physiques (issue incertaine). À trancher par GoFix Digital ; l'option 1 est la plus rapide.

3b

Activer les notifications push 30 min (une seule fois)

L'application demande l'autorisation après la connexion, en expliquant d'abord à quoi servent les notifications (réponse d'un pro, nouveau message, rendez-vous). Le serveur envoie ensuite les alertes via le service push d'Expo, qui les relaie à Apple et Google. À configurer pour les builds des stores :

  1. npx eas-cli@latest init (étape 3) ajoute l'identifiant du projet Expo dans app.json : il est nécessaire pour obtenir le jeton de l'appareil.
  2. Android : créer un projet Firebase (console.firebase.google.com) → ajouter une application Android dz.gofix.app → télécharger google-services.json dans mobile/ et ajouter "googleServicesFile": "./google-services.json" dans la section android de app.json ; puis Firebase → Paramètres → Comptes de service → générer une clé privée et l'envoyer à Expo avec npx eas-cli@latest credentials (Android → « FCM V1 service account key »).
  3. iOS : rien à faire à la main — lors du build, EAS propose de créer la clé de notifications Apple (APNs) : répondre Oui.
  4. Reconstruire l'application (étape 3), l'installer, accepter les notifications, puis vérifier : un message envoyé depuis un autre compte doit faire apparaître une notification, et la toucher doit ouvrir la conversation.

Bon à savoir

  • Dans Expo Go, les notifications distantes ne fonctionnent pas sur Android : les tester avec le build preview.
  • Coupure générale possible depuis le back-office : flag push_notifications. L'utilisateur peut aussi les couper dans les réglages du téléphone ; à la déconnexion, le téléphone cesse de recevoir les notifications du compte.
  • La localisation est facultative et approximative : elle ne sert qu'à proposer la wilaya (bouton « Détecter ma wilaya » et « Près de moi »). La position n'est ni enregistrée ni journalisée par GoFix.
